# 4.3 Микросервисная архитектура (Microservice-Oriented Development)

Проект построен на базе современной распределенной микросервисной архитектуры, развернутой в изолированном окружении **Docker**. Использование контейнеризации позволяет добиться высокой степени масштабируемости, надежности и независимости развертывания каждого отдельного компонента системы.

## Диаграмма инфраструктуры Docker-микросервисов

### Описание компонентов инфраструктуры

1. **Nginx Reverse Proxy:** Выступает в роли единой точки входа (Single Entry Point) для всей системы. Он принимает все внешние запросы на порту `8000`, разграничивает статический контент фронтенда (React React SPA) и динамические запросы к API, проксируя последние в `API Gateway`.
2. **API Gateway:** Является внутренним оркестратором. Обеспечивает единую аутентификацию на основе JWT-токенов, валидацию базовых параметров и маршрутизацию трафика к изолированным микросервисам внутри сети Docker.
3. **User Service:** Сервис, отвечающий за регистрацию пользователей, управление их профилями, безопасное хэширование паролей (bcrypt) и авторизацию.
4. **Upload Service:** Обрабатывает загрузку файлов (аудио/видео) различных форматов, выполняет первичную валидацию, сохраняет медиаданные во временное хранилище и публикует задачи на транскрибацию и анализ в брокер сообщений `RabbitMQ`.
5. **AI Processing Worker:** Python-сервис, выступающий в роли обработчика очередей. Потребляет задачи из RabbitMQ, извлекает аудиодорожки при необходимости, взаимодействует с API **Google Gemini** для получения транскрипций, резюме и интерактивных материалов, после чего напрямую записывает результаты в PostgreSQL.
6. **Search Service:** Обеспечивает высокоскоростной полнотекстовый поиск по текстам транскрипций и истории анализов. Интегрирован с `Redis` для кэширования частых поисковых запросов и разгрузки основной реляционной базы данных.
7. **PostgreSQL & Redis & RabbitMQ:** Системные ресурсы, развернутые в отдельных контейнерах, изолированные от внешнего мира и доступные только для микросервисов внутри `transcription-network`.
